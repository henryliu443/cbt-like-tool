# 迁移与重构阶段进度快照

## 本次完成了什么
完成了 Android 原生与 KMP (Kotlin Multiplatform) 共享层的全面实施与合并：
1. **KMP 基建搭建**：成功创建了共享核心模块 `shared`，配置了跨平台 `Ktor` 网络层和 `kotlinx-coroutines` 并发支持。
2. **本地持久化与数据映射**：在 `shared` 模块中引入了 `SQLDelight` 数据库，映射了原先 iOS `SwiftData` 的数据结构，实现了 `HistoryRepository`。
3. **依赖注入与安全**：引入了 `Koin` 全局依赖注入框架，并且基于 `Multiplatform-Settings (Encrypted)` 实现了 API Key 的加密存储。
4. **Android 平台特性**：封装并实现了 Android 端基于 `BiometricPrompt` 的指纹/人脸解锁逻辑。
5. **Android UI 骨架与动画**：使用 Jetpack Compose 重构了 UI 主干（打字机流式输出、历史卡片列表），并添加了丝滑的过渡动画。
6. **合流主分支**：解决了分支差异导致的文件删除风险，安全地将整个 Android/KMP 架构代码合流（Merge）入默认的 `main` 主分支，使 `main` 同时包含 Android、iOS 和 KMP 共享层代码。
7. **发布测试包**：在 GitHub 远端发布了 `dev0.0.1` 标签并自动编译上传了 `CBTReframe_dev0.0.1.apk` 调试安装包。

## 遇到的关键决策或问题
1. **分支合并的文件删除冲突**：在将 `android` 分支合入 `main` 时，由于早期 `android` 分支移除了 iOS 相关的 xcodeproj 目录，普通 Merge 会导致 `main` 上的 iOS 代码被连带删除。决策：回滚后使用 `git checkout android -- <paths>` 精准提取安卓相关文件，确保 iOS 与 Android 在主分支安全并存。
2. **KMP build.gradle.kts 声明冲突**：`iosArm64()` 等 Target 配置中曾出现由于 dependsOn 循环嵌套导致的编译警告与报错。决策：优化了 Gradle 源集 (SourceSets) 的依赖关系，对 `iosMain` 及对应的架构子集依赖做了清晰规整。
